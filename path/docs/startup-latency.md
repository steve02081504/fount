# CLI Startup Latency

Why the path CLI and the Windows runner are structured the way they are. Keep these properties when editing `path/src/**` or `src/runner/main.{ps1,sh}`. Overview: [path AGENTS](../AGENTS.md), [runner AGENTS](../../src/runner/AGENTS.md).

## path CLI

Kept fast for short commands (e.g. `fount eval`): on PowerShell `bootstrap_full` only `require_base`s (env, refresh_path, deno, fs, run, first_install), and `fount_first_install_if_needed` calls `require_mid` **inside** its install branch, so an already-installed tree never parses the ~0.4s registration/update module set. Heavy load-time side effects are likewise deferred: the Clash TUN and pwsh-module updater `Start-Job`s (~0.5s each; killed on short-command exit) run only from `bootstrap_server` / first install, `win/app_restart` and `win/explorer_refresh` compile their C# on first use, and `profile.ps1` skips the `Get-Module fount-pwsh` scan when `$Profile` already imports it. The sh side mirrors the Clash deferral (`enable_clash_tun_background`, called from `first_install.sh` / `bootstrap_server`); its module sourcing is already sub-millisecond (~150µs each), so no `require_base` split is needed there.

The shared prelude is lean and lazy rather than per-command special-cased. PowerShell `index.ps1` eagerly loads only `env`/`terminal`/`temp_guard`; `i18n` is a lazy proxy installed by `load.ps1` (first `Get-I18n` sources `i18n.ps1` and replaces the proxy; skipped when the runner already defined it), `eula` is required only when the first-run gate fires, and `passthrough` is required only when `$IsWindows` is false (MSYS/Cygwin). `fount eval` calls the shared WS client `src/scripts/eval.mjs` from both `path/src/cmd/eval.ps1` and `path/src/cmd/eval.sh` (the wrapper only forwards its args — no locale/env plumbing): the server streams `eval_output` frames as they are produced and finishes with `eval_result`, rendering text server-side because the client asks with `text: true` (+ `ansi` when stdout is a TTY). The client lazily reads `fountConsole.path.eval.*` only when it must print an error, so the CLI prelude never loads i18n. The compiled host only consumes stdin when the embedded script uses `$input` ([ps12exe#62](https://github.com/steve02081504/ps12exe/issues/62), fixed), so the `deno` child reads raw stdin directly. Runner `Set-ExecutionPolicy` is guarded by a direct registry read (skips the ~0.3s ExecutionPolicy module load when already `Unrestricted`). Launcher/`fount eval` startup: bench with [tools/bench/cli_startup.mjs](../../src/scripts/test/tools/bench/cli_startup.mjs) (`fount nop` floor + `fount eval` echo vs `deno eval` / `pwsh` / `powershell.exe`).

## Windows runner

The compiled exe runs the path CLI **in-process** with `& path/src/index.ps1` (child scope, so the runner's variables are not merged; the script's `exit` only sets `$LastExitCode` and returns, as in `path/fount.ps1`, so the runner reads it back) — `index.ps1` always exists in a valid tree, so no `run.bat` fallback. This skips the `run.bat` → `fount.bat` → fresh `pwsh` round trip (~1s). The current-user execution policy is read straight from `HKCU:\Software\Microsoft\PowerShell\1\ShellIds\Microsoft.PowerShell` and `Set-ExecutionPolicy` runs only when it is not already `Unrestricted` (the cmdlet's first call loads a ~0.3s module otherwise). The exe host only drains redirected stdin when the embedded script uses `$input` ([ps12exe#62](https://github.com/steve02081504/ps12exe/issues/62), fixed), so `cmd_eval` reads raw stdin directly and the runner forwards nothing. The Clash TUN `Start-Job` is only spawned from `Install-FountTree` (fresh clone needs it; afterwards the path CLI handles install/server) — `main.sh` mirrors this with `enable_clash_tun_background` called from `install_fount_tree`. The compiled-exe self-update preprocesses `main.ps1` with `ps12exe -PreprocessOnly` only when the source mtime is newer than the exe, instead of on every run (the sh runner already uses a cheap `cmp -s`).
