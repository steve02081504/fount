# 远程长期回调会话

## 模型与边界

一次远程执行的 Promise 表示执行完成，不能同时承担长期订阅的所有权。长期回调使用独立会话：`open` 初始化生产者，`ready` 返回初始化结果，随后持续接收 `event`，直到取消、生产者结束、断线或租约过期。

`createTargetExecutor(...).openCallbackSession(script, { onEvent, onClose, signal })` 立即返回 `{ id, ready, dispose }`。句柄在初始化完成前就能取消；`ready` 只表示初始化完成，不等待长期事件循环。远端初始化代码注入 `callbackSession`：

- `emit(data)`：提交 JSON 事件，返回是否接收；事件队列及单帧大小有上限。
- `onDispose(cleanup)`：登记资源清理。清理必须快速释放监听、定时器、连接等资源；异步清理异常被隔离，系统不等待无期限循环。
- `signal`：协作取消信号；取消期间新登记的清理函数立即执行。
- `close(reason)`：生产者主动结束会话，立即释放资源，已接收事件先发送及消费完毕，再通知结束；取消、溢出或传输失败可以直接丢弃剩余队列。

该接口适用于文件、进程状态、日志、设备输入、远程服务事件等生产者。订阅不写聊天时间线，也不是统一 async-task 的后台计算任务；需要持久化业务结果时，由消费方决定如何记录。

## 线协议与所有权

复用 subfount 房间的自定义 action：`callback_session` 承载 `{ id, op: open|renew|cancel, script? }`，`callback_session_event` 承载 `{ id, type: ready|event|heartbeat|end, result?, seq?, data?, reason? }`。所有分机直接使用统一的回调会话协议。

会话属于创建它的已认证主机及具体设备链路。主机校验事件来源与会话绑定，分机只接受本会话的已认证主机控制消息。`id` 每次新建，断线后重建不会接受旧订阅的迟到事件。

生产者先发送 `ready`，再串行发送初始化期间缓存的事件。事件序列从 1 开始；消费者忽略重复，发现缺口则结束会话；异步消费者按序执行，其待处理队列同样限制为 64 项、1 MiB，拒绝或溢出会结束会话。这里提供有界的实时事件流，不保证断线重放或业务操作恰好执行一次。需要这些语义的生产者应使用业务游标及持久化存储。

## 生命周期与故障

主机每 10 秒续租，分机返回心跳；30 秒没有续租则释放资源。主机在心跳超时或收到链路断开事件时结束会话。初始化也有独立的 30 秒期限，心跳不能无限延长一个从未 ready 的初始化。

每主机会话运行时最多 128 个生产者；每个生产者最多缓存 64 个事件、总计 1 MiB，单帧上限 256 KiB。溢出或发送失败会释放生产者并结束会话，消费方据此重建或报错，避免无声丢弃事件。取消幂等，短期有界 tombstone 防止先到达的取消消息被迟到的 open 覆盖。用户删除、管理器替换、分机主机配置删除和停机也释放会话。

取消不能强制中断任意 JS 无限循环，生产者必须遵守 `signal` 并及时登记清理。断线时不自动重新执行初始化脚本：它可能有业务副作用。重连策略属于消费方。

## code shell 的消费策略

工作区生产者在目标机器校验 realpath 边界，监听根目录、展开目录和打开文件的父目录；120 毫秒内的文件变化合并成一个失效通知。单次订阅最多 128 个目录。

页面收到 `ready` 或 `change` 后重新读取可见目录和打开的文件，连续通知合并为串行刷新。已有未保存编辑保持原样，磁盘变化只标记冲突。断线提示持续显示，直到新的订阅 ready；重连后的重新读取覆盖断线期间的变化。页面关闭或工作区变化会取消旧会话。

浏览器到主机的 WebSocket 同样发送心跳，避免链路静默失效时继续显示已连接。无效订阅显示自动更新不可用；暂时断线自动重试。fount-p2p 现有 action、发送结果和 link join/leave 已满足需求，无须增加文件监听特定协议。
