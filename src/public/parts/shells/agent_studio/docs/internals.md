# Agent Studio Internals

Deep reference for generation records, replay and the frontend views. Day-to-day rules: [AGENTS.md](../AGENTS.md).

## Generation records

- Prompt privacy: `single_part_prompt_t.encrypted = true` masks that part's text and additional context; `text[].encrypted = true` masks individual text blocks. Agent Studio projects a redacted copy before system/message rendering, attachment capture and the source's `BuildPrompt`, so UI, API and CLI snapshots all contain meow prose instead of the marked text. The actual model request retains the original prompt. `src/prompt_redaction.mjs` estimates each complete marked block with `estimateTokenCount` and generates ASCII prose with the same estimated token count (not an exact provider tokenizer count). Punctuation is pseudo-random but deterministic per input to preserve cache-prefix comparisons. Encrypted additional context drops its attachments. This is recording-time masking, not cryptographic encryption; existing history and model outputs are not retroactively redacted.

- Record shape: `{ id, parentId?, charId, charname?, subAgent?, chatId?, conversationId?, source, startedAt, finishedAt?, input?, requests?, requestCount?, dialogue?, response?, conversation?, model?, metadata?, error? }`. `input` is a legacy request `chat_log` snapshot (not the assembled prompt). `requests` is the per-round AI request snapshot: `{ index, startedAt, finishedAt, model, systemPrompt, messages, snapshot?, output?, usage? }` (`systemPrompt` = merged system prompt, `messages` = visible chat log after `mergeStructPromptChatLog`, each message carries an `id` and a `type` when the source entry had one — `cache-report` uses `type: 'summary'` to exclude compression rounds; `snapshot` = the AI source's `BuildPrompt` output deep-serialized to plain text, binary hashed — see below; `output` = the raw model output, used as the next round's cache basis — see below; `usage` = the calls that request itself added, recorded by slicing the reply's cumulative `extension.usage` at the call count captured when the request began, so a replayed `base_result` never double-counts earlier rounds). `dialogue` is the reconstructed conversation `{ rounds, events }` derived from `requests` + the final reply.
- **Reconstruction** (`public/shared/dialogueReplay.mjs`): messages align by `id` across rounds; new char/tool messages first visible in request *N+1* are outputs of round *N* (not future prompt inputs); user/system inputs and edits stay at their request round. The final reply belongs to the last round. `getGeneration` rebuilds the dialogue from retained requests at read time so existing records with prompt snapshots also display the corrected chronology; when requests expire, the retained dialogue is used.
- Conversation grouping: `conversationKey = conversationId || chatId || id`; `summarizeConversations` (both in `public/shared/generationChain.mjs`) powers `listConversations` / `getConversation`. `generationRoundSpan(record)` (same module) is the single authority for a generation's round span (`max(requestCount, requests.length, dialogue.rounds, 1)`), shared by `mergeDialogueEvents` and the frontend `buildRoundUnits` so their offsets can never drift. `getConversation` merges per-generation `dialogue` events (rounds offset in start order) into one continuous `dialogue` (`{ rounds, events, messages }`); a generation whose final reply was superseded (the next generation replayed the same user turn without carrying that reply) has that reply dropped from the merged transcript, so a re-run/continuation does not stack parallel answers.
- Attachments: request `messages[].files` capture immutable bytes before generation (`snapshotAttachment` is called from `chat/src/prompt_struct/snapshot.mjs`, so the chat manifest watches `src/attachments.mjs`); persistence replaces payloads with `{ hash, byteLength, name, mime_type, description }` and stores one SHA-256-keyed blob per user under the same temp store (`attachments/<hash>`). Record JSON files (including retained dialogue/conversation) are the reachability roots. Pruning, clearing and record replacement sweep unreachable blobs; corrupt roots abort sweeping. Authenticated attachment delivery checks retained references and supports byte ranges and downloads. No prompt or attachment data belongs in shell settings.

## Prompt cache estimate

- Prompt cache UI is a **character-based estimate**, not provider-billed cached tokens. `finishPromptRequest` captures each model output (`requests[].output`); `public/shared/promptCache.mjs` compares the previous request's `snapshot` (AI source `BuildPrompt`, serialized by `chat/src/prompt_struct/serializeSnapshot.mjs`; fallback: `systemPrompt` + `messages`) to the next request, then adds the previous output to both the denominator and the reused count only when it is the next request's first added char message. JSON snapshot container closers are excluded from the comparable prefix. Old records recover missing output from the next request's char message or the previous generation's final response. Per-round rate = reused / (previous comparable prompt length + output length); a generation's `rate` is the arithmetic mean of its non-null rounds.
- `recordGeneration` precomputes each record's `cacheRate` (reading the conversation's previous record's last prompt) and stores it in the index summary, so list badges survive `requests` stripping. Aggregates: `summarizeConversations` → `minCacheRate`, `summarizeSubAgentRuns` → `minCacheRate`, `minCacheRateByChar` → per-char `minCacheRate` in `/chars`. The frontend `lib/cacheBadge.mjs` renders these on char / conversation / run list items.
- In the current conversation view, `renderTranscript` replays a single deduplicated dialogue history to the selected round; each model-generated char entry owns its expandable request prompt and per-round cache badge. The timeline/chart remain per-request, while changing the slider updates one transcript rather than stacking generation/round cards. Sub-agent live entries use their live conversation at the latest node and the recorded replay at earlier nodes.

## Frontend views

- Four main views, each `<section id="<view>View" class="view">` in `public/index.html`: `dashboard` (char list + overview, sub-agent run cards and conversation list), `generations` (conversations + chains, char filter), `benchmarks` (defs + runner + JSON import/export + results), `settings` (retention). `#conversation/<key>` is the only detail view, including `#conversation/subagent%3A<runId>`; its replay slider / timeline is **per round** (`buildRoundUnits` expands each generation into one unit per `requestCount` / `dialogue.rounds` — the span formula must stay identical to `mergeDialogueEvents`, else replay misaligns; generation boundaries are the `generation-start` nodes). `renderTranscript` replays one deduplicated dialogue transcript to the selected round; each model-generated char entry carries its round's cache badge and its own collapsible prompt, and the final-reply entry carries the response copy/download actions (a char entry whose request expired renders the prompt gap hint instead). Within a prompt, the contiguous character prefix shared with the previous request (system prompt + message contents in order, matching `estimatePromptCache`'s prefix semantics) gets a `--color-success` tint cut exactly at the first differing character, clamped to what the outbound snapshot proves was reused (`snapshotReuseLengths` maps the snapshot's common prefix back onto each block, and returns `null` when either request has no snapshot), with a zero-width boundary marker and a jump button that opens the panel and scrolls to it. The cache-rate chart is **per round** (one point per timeline node, each round's own request-vs-previous rate from `estimatePromptCache`'s `rounds`). Below the replay panel, `renderLowRates` lists the 7 rounds with the lowest finite per-round `rate` (same `rounds[].rate` source as the chart), each a button that jumps the slider to that round and scrolls to its transcript entry (`data-round`). `messageBody.mjs` gives every message a Markdown/plain-text switch, defaulting to plain text; it takes `collapseLines`, so a `tool`-role entry whose output exceeds 7 lines starts collapsed behind an expand/collapse toggle (the threshold constant lives in `views/conversation.mjs`). Every prompt text block (system prompt / messages / response / sub-agent task / generation-dialog prompt & response) carries copy + download `.section-actions` (`lib/textActions.mjs`; `shared/promptText.mjs` serializes message arrays) for the prompt-improvement flow. The sub-agent transcript is fetched from its live run while active, from persisted history afterward; its composer is shown only at the latest replay node while `canSend` is true. `src/viewChrome.mjs` toggles visibility/highlight; `src/navigation.mjs` maps view → loader, syncs `location.hash`, and wraps switches in a View Transition.
- `src/views/*.mjs` own rendering; loaders are safe to re-run (language change re-invokes the active view). Templates live in `public/src/templates/`; `public/src/lib/` holds `format` / `emptyState` / `generationDialog` / `activate` / `generationItem` / `charOptions` / `stateBadge` / `navigationEvents` / `metaChip` (`.meta-chip` builder + `appendMetaChips`) / `cacheBadge` (`createCacheBadge` + shared `CACHE_GOOD_RATIO` threshold) helpers. No view imports `navigation.mjs` (avoids a cycle); the subagent back button dispatches a `navigationEvents` request that `installNavigationEvents` (called in boot) turns into `switchView`.
