# Code Shell UI Details

Deep implementation walkthrough for `shells/code` (`public/index.mjs`, `public/src/`, `src/`). The concise guide, contracts, and repo-wide traps live in [../AGENTS.md](../AGENTS.md). UI / layout / interaction mechanics belong here or in `AGENTS.md` — never in `public/llms.txt`.

## Layout

Topbar left = `#home-toggle` (opens the two-pane workspace / conversation picker, see below) + `#tab-strip` (`#new-tab-button` rendered inside the strip, scrolls with the tabs); there is **no left sidebar** — mobile has no drawer. Topbar right = `#code-context`, a compact context chip: a workspace button (folder icon + workspace name, opens the home picker) and a char button (robot icon + char name, opens the char switch dialog). It is `hidden` in empty mode (the full `.code-composer-targets` row is visible there) and shows only the buttons that have a value. The composer card's `#composer-controls-main` row holds mode / AI source / shell pills below the input (all `dropdown-top`, row must **not** set `overflow: hidden`); the power icon button (`#power-settings-button` + `#power-armed-badge`) sits between that row and the send button, **inside the card**. A centered `.code-composer-hint` + `.code-composer-targets` row sits **below the card** with the machine / workspace / char pills, but both are hidden whenever `.code-main` is **not** `.empty-mode` — once the active session has entries (or is generating), the chrome collapses to give the message flow the viewport; only empty drafts show the full pickers. `.code-topbar` gains `.scrolled` (a soft shadow) while `#messages` is scrolled away from the top.

## Home picker

`#home-toggle` → `home.mjs` `openHomePicker`: two-pane dialog (`public/src/templates/home_picker.html`): left = workspaces, right = the selected workspace's conversations. Left-click a workspace only switches the right pane; its delete button runs `removeWorkspaceById` (`confirmAction('code.workspaces.removeConfirm')` — removes the saved entry only, disk session files stay). A conversation row click runs `openSessionTab` and closes the dialog; its delete button runs `deleteSessionPermanently` (confirm → `closeTab(tab, { discard: true })` → `DELETE /sessions/:id`, so the flush can't recreate the file). Language switch / data refresh re-renders via `refreshHomePicker()`.

## Tabs

`#new-tab-button` is rendered by `renderTabs` **inside the strip, right after the last tab** (scrolls with the tabs; `replaceChildren` would wipe a static HTML button). Each `.code-tab` has hover close, middle-click, and a **right-click context menu** (`showTabContextMenu`: rename / delete conversation / close / close others / close left / close right / close all; rename and delete-conversation are session-only, delete reuses `deleteSessionPermanently` (confirm → discard-close → `DELETE /sessions/:id`); rename prompts via `promptText('code.tabs.rename')`, loads the session on the tab's own workspace when uncached, and persists the title via `PUT /sessions/:id`) using the static `#code-tab-menu` + `positionContextMenu`/`bindDismissOnDocumentInteraction`; unavailable items are omitted; the actively generating tab can't be closed. `startNewSession` **always creates a new draft tab** (no reuse of an empty draft) — multiple draft tabs coexist; empty drafts are no longer discarded on switch. Workspace pill switch rebinds the current *empty* active draft to the workspace (`activateDraftForWorkspace`) instead of leaving a no-workspace orphan. The tab list + each tab's unsent composer draft persist to backend `code.tabs` (debounced `PUT /tabs`, flush on blur/hidden/unload) and broadcast on `BroadcastChannel('fount-code-tabs')`; receivers re-render the strip but keep their own active tab and draft (`applyRemoteTabs`). Draft text is per-tab: `syncActiveTabDraft` on input, `current.draft = richInput.value` on switch, `restoreTabDraft` on activate.

### Notification-driven tab dot + `?session=` deep link

Generation-completion notifications arrive as the page-global `fount-notification` event (`base.mjs` relays the SW message; `index.mjs` → `bumpCodeSessionNotification`), which adds a `.code-tab-unread` dot to the originating tab (`tag: code:<sessionId>`); activating the tab clears it, and the tab that is already active is skipped. `syncCodeUrl` mirrors the active tab into the address bar — **only session tabs** write `?workspace=&session=` (a draft clears the query) so a reload restores instead of being parsed as the `fount run` `?workspace=` "new draft" semantics. `boot` restores `?session=` by focusing an open tab or creating one from disk.

### Pill selectors

Pill selectors replace native `<select>`: daisyUI `dropdown` + `.code-pill` (label span + chevron). Menus are rendered by `render*Menu()`; items call `document.activeElement?.blur()` after click (daisyUI 5 trigger gets `pointer-events: none` while open).

## Dialogs & folder browser

Dialogs go through templates: `public/src/templates.mjs` binds `dialogsFor('/parts/shells:code/src/templates')` — `command_params`, `char_switch`, `ai_source_panel` live in `public/src/templates/*.html`. Open via `openDialogFromTemplate(name, data, { onReady })`; do not hand-write `<dialog>` in `index.html`. The folder browser is a **shared component** (`/scripts/components/folderBrowser.mjs`, template at `/scripts/features/templates/folder_browser.html`, i18n under `util.folderBrowser.*`); `pills.mjs` `openFolderBrowser()` is a thin wrapper passing `browse: (path, ws) => api.browseMachine(store.machine, path, ws)`, `onSelect` (add workspace + reselect), `dirsOnly: true` (workspace picker hides files) and the current workspace for the quick-access group.

The dialog opens **immediately with a loading placeholder** (`util.folderBrowser.loading`) and renders once browse returns — the root view's quick-access build (editor scan + volume labels) is slow, so a blocking `onReady` would delay the popup. Opens at drive roots / `/`; the root view is prefixed by a quick-access group — **editor-sourced projects (VS Code/Cursor/JetBrains recent) always show as "recent projects", even with no active workspace**; workspace siblings and `.git`-bearing subdirectories are added only when a workspace is active. The top path input doubles as a filter (last path segment matched case-insensitively, ↑/↓ move highlight, Enter opens the highlighted entry or falls back to the typed path); editing the path's directory part (last `[/\\]` and earlier) clears the selection and makes Enter jump to the typed path; Go / Enter navigates by path; single-click a directory enters it; the select button closes the dialog and adds the current path as a workspace.

## Shell mode, history, ghost

**Shell mode (`！`/`!`)**: entered from an empty composer via the `input` handler; the `！` is **removed immediately** (`richInput.value = ''`) so the user types a clean command. **Send (button / Ctrl+Enter) keeps shell mode** for consecutive commands — it exits only on **Backspace while the whole input is empty** (deleting content down to empty does NOT exit). Shell pill (`#shell-pill-wrap`) shows as the mode indicator; the other controls fade via `.code-composer-shell.shell-mode .code-composer-controls-main > :not(#shell-pill-wrap)`. UI copy uses a single `!`; code accepts both `！` and `!`.

**Input history + ghost (both modes, independent)**: `historyState` holds `own` (workspace `.agents/fount/code/{shell,message}_history.json`, localStorage fallback for message without workspace) + `native` (shell only). ↑/↓ navigate own history **only when the caret is on the first/last line** (`isAtFirstLine`/`isAtLastLine`); a `.code-composer-ghost` span (`contenteditable=false` + `data-emptySlot` so serialization skips it) shows the prefix-match remainder when the caret is at the end; **Tab / ArrowRight accept the ghost**. `updateGhost` runs after every `input` (markdownRichInput rebuilds the DOM each input, so the ghost is re-added each time).

**Workspace char override**: on `selectWorkspace`, `applyWorkspaceCharConfig()` reads `.agents/fount/code.json` (`{ char: { partname, install_url } }`) — installed → auto-select; missing → bottom-right `.code-char-recommend` card (install via `runPart('shells/install', ['install', url|partname])`, dismiss is not persisted).

## Send, empty states, scrolling

- **Send / stop**: `#send-button` is an icon button (`updateSendButton` swaps arrow-up ↔ stop square + `stop` class). **Ctrl/Cmd+Enter sends**. Tab accepts a ghost when present, else cycles mode (message mode only).
- **Empty states**: `renderEmpty()` inside `#messages` — no workspace → guidance card with CTA that opens `openFolderBrowser()`; workspace but no session → "start a new coding session". No empty `div` black hole.
- **Scrolling**: stick-to-bottom auto-scroll (tolerance `SCROLL_TOLERANCE`), "back to bottom" floating button (`#code-back-to-bottom`) appears when scrolled up.

## Slash / mention

- **`/` commands panel / `@` autocomplete** consume `state.commands` (merged builtin/global/workspace lists from `GET /profiles`), `GET /files/search`, and the gist list (`/parts/shells:gist/src/endpoints.mjs` `listGists`, 30s memo). One combined provider runs gists + workspace files (`composer.mjs` `mentionProvider`) since the shared picker takes the first non-`null` provider. Selecting a gist inserts `@[gist:id]` (chip label from `store.gistTitles`, filled at suggest time); **`sendMessage` expands `@[gist:id]` into a `text/markdown` attachment** (title-derived `.md` name) merged with `pendingFiles`, so the char receives the gist body via `files` — the token stays in the message text. Slash panel is a `.code-slash-panel` card anchored above the composer; mention panel is `.mention-panel` (styled in `index.css`).

## Message chrome & bubbles

- **Message chrome templates**: `message_editor` / `feedback_reason` (`public/src/templates/*.html`) render the inline edit / feedback-reason forms; `char_menu_footer` supplies the char pill menu footer. `renderTemplate` returns the single root element for these one-root templates (not a fragment) — use it directly.
- **Message bubbles**: `.code-messages` horizontal `padding: max(1.25rem, 15%)` carves out a **centered 70% column** (narrow screens fall back to plain margins): `.code-message.role-char` hugs the column left (no `margin: auto`), `.code-message.role-user` `margin: 0 0 0 auto` hugs the column right edge (flex cross-axis auto margins beat `align-self`). The composer card / hint / targets sit inside `.code-composer` which shares the same padding, so they line up with the column for free (no per-element `max-width`). Tool/system entries render as `details.code-tool-log`; the summary label is localized by `toolDisplayLabel` (`code.tool.*`), so plugins should give each tool a distinct dot-namespaced `name` (`file-operations.view-file`/`glob`/`grep`/`replace-file`/`override-file`, `code-execution.run-<shell>`) rather than one blanket plugin name. A name outside the map falls back to the triggering XML tag parsed from the call card (`toolTagName`), then to the raw `name`. Entries with `name === 'shell'` (user `!` exec results), `sub-agent.check`, or a `code-execution`-prefixed name render **open by default**. Raw char generations that only call tools have their handled calls stripped from `content_for_show` by `runReplyHandlers`, and `isEntryVisible` skips entries with no visible show text and no files — so no empty bubble is left behind. Bubbles render `entry.content_for_show ?? entry.content` (agent `content` vs human `content_for_show`); copy / save-as-HTML / drag-export likewise use the show layer, while edit edits `content_for_edit ?? content` and clears the show/edit overlays.
- **Tool cards**: three extension-driven render paths sit before the generic `details.code-tool-log` — `extension.subAgent` → sub-agent status button (`subAgentCardElement`, click opens Agent Studio at `#subagent/<runId>`); `extension.asyncTask` → **non-interactive** async-task status card (`asyncTaskCardElement`); and inside the details body, `extension.subAgentCheck` / `extension.asyncList` / `extension.asyncAwait` replace the markdown body with structured cards (`renderSubAgentCheck` = role-tagged transcript + "open in Agent Studio"; `renderAsyncList` / `renderAsyncAwait` = snapshot task rows + result markdown — the state badge is rendered only when the payload carries a terminal `state`, so persisted `<list-async/>` / unsettled rows never fake "running"). Both status cards share `public/src/runCards.mjs` (`createRunCard` / `paintRunCard` + a registered `createRunCardFeed`), so their live state is updated in place by `updateRunCards()` after every (re)render and by `refreshRunCards({ force: true })` on tab switch / generation end, from `subagent-run` / `async-task` server events and `GET …/subagents` / `GET …/async-tasks`. All of these extensions are persisted through `code/src/entry_extension.mjs` `pickEntryExtension` (the whitelist applied by `sanitizeEntry` on the WS `done` path) — add a new render field there or it is stripped before it reaches the page. Code blocks inside these cards render through the shared markdown pipeline, so they get shiki highlighting once the page's `color-scheme` attribute is set.
- **Message actions**: hover action bar (`.code-message-actions`, shown on hover/focus-within; **always visible at low opacity under `@media (hover: none)`** so touch devices can act) is anchored to the **bottom of its own message** (`top: calc(100% - 0.25rem)`; char messages sit on the feedback row via `bottom: 0`) — never above the bubble, or the next message's bar looks like it belongs to the previous one and gets mis-clicked (copying a neighbour). Copy (whole entry); edit (user/char); save-as-HTML (char only). Edit = inline `.code-message-editor` (textarea + save/cancel), changes only `entry.content` without resending, then `markSessionDirty` + full re-render on save. Save-as-HTML / drag-export share `renderMarkdownAsStandaloneDocument` + `downloadHtmlDocument` (`/parts/shells:gist/src/standaloneDocument.mjs`). Drag-export (`bindMessageDragExport`): sets `draggable` only when `mousedown` lands outside the body/buttons (so body text stays selectable); `dragstart` sets `text/plain` + `DownloadURL` (the standalone HTML blob is prebuilt on `mousedown`).
- **Feedback / regen**: inline feedback bar on char messages (`.code-message-feedback`, low resting opacity): 👍 toggles directly, 👎 opens an optional reason area (`.code-message-feedback-reason`); stored as `entry.extension.feedback = { type, content, time }` in the session JSON (local marker only, not used for regeneration). ↻ regenerate (`renderCharFeedback`'s `.code-message-feedback-regen`) shows only when the message is the last entry, a char role, and not currently generating (`updateRegenButtons` refreshed by renderMessages / appendEntryBubble / updateSendButton): frontend pops the old reply → WS `{ type: 'regen' }` → streaming preview reuses the generating bubble → `done` appends the new reply.
- **Composer attachments**: `#attach-button` (front of controls-main) opens the hidden `#attach-input`; pasted files (`paste` event `clipboardData.files`) and files dropped on the composer (`.code-composer-shell` dragenter/leave counter + `#drop-overlay` veil) join the same queue. Pending attachments live in `state.pendingFiles` (`{ name, mime_type, buffer: base64, description }`, 10MB per-file cap); `#attachment-preview` strip chips are removable. On send they merge into the user entry via WS `send.files` (`request.mjs` `sessionToChatLog` decodes base64 → Buffer into `chat_log`, visible to the char); cleared after a successful send.

## Streaming & real-time tool output

- **Streaming**: `boot` calls `warmupMarkdownPipeline()` to preheat both markdown pipelines (trusted tier = bubble body / safe tier = StreamRenderer preview) — registry + dynamic extension loading is a cold start, and without preheat the first preview window stalls (generating bubble stays blank). `updateEmptyMode` treats "currently generating this session" as non-empty (otherwise `.code-messages` gets swallowed by empty-mode `display:none` and the streaming bubble has no container). The generating bubble (`startGeneratingBubble`) is marked `user-content` like regular bubbles, or the page-watch locale scan warns. Frontend tests hold locale rotation with `fount.test.watch.holdLocale()/releaseLocale()` during dropdown interactions (the per-second full-page rebuild races clicks).
- **Real-time tool output**: `!` mode goes through `api.streamExec` → WS `/ws/parts/shells:code/exec` (`{id, machine, workdir, shell?, command}` in; `output` / `done` / `error` out): `execShellMode` creates the `name:'shell'` tool entry immediately with `extension.shellStream = { command, shell, output }`, accumulates frames, updates the bubble per animation frame via `updateShellStreamBubble` (writes the `<pre class="code-shell-stream-output">`), then deletes `shellStream` and finalizes `content` (markdown + elapsed) via `updateEntryBubble`. AI `<run-*>` / `<inline-*>` output arrives on the session WS as `tool-output` (`{callId, phase: start|chunk|end, name, lang?, code?, stream?, data?}`) — `handleToolOutput` builds a `.code-tool-live` card inside the generating bubble (`createLiveToolCard`) and appends chunks; `endGeneratingBubble` clears the cards (the `done` entries are the authoritative logs). The session WS `preview` carries `content_for_show ?? content` so streaming shows the tool-replaced layer.

## Power actions

**After-tasks power action (`#power-settings-button`, `#power-armed-badge`)**: an **icon button inside the composer card** (between `#composer-controls-main` and the send button — not a pill, not a separate row), opens the `power_settings` dialog (`power_settings.html`). It stays visible in both empty and conversation mode (the collapsing chrome never hides it) so an armed action can't be forgotten: `renderPowerButton()` toggles `btn-warning`, overlays `#power-armed-badge` with the host count (`hidden` at 0), and sets `aria-label` from `code.power.armedAria` (armed) / `code.power.settings.aria` (idle) — the `title` is owned solely by the button's static `data-i18n="code.power.settings"` (`code.power.settings.title`). Each host (local + connected subfounts; only local when none) has a `select` for the action — none / shutdown / sleep / restart; selecting a non-none action `PUT /shutdown {machine, action}` arms it, `none` cancels that host. Multiple hosts can be armed at once. State is backend-global per user (`GET /shutdown` returns `{ actions: { [machine]: action }, active }`); `refreshShutdownState()` runs on boot and after each `finishGeneration`, `renderPowerButton()` is re-run on language change. Host names use `machineDisplayName` (shared with the machine pill; remote names marked `user-content`).

## Backend internals

- `runner.mjs` `runShellCommand` streaming plumbing: `onOutput` streams chunks: local via `@steve02081504/exec` `on_stdout/on_stderr`; remote via `executeCodeOnSubfount` + `callback` (`callbackPartpath: 'shells/code'`, `main.mjs` `interfaces.subfount.RemoteCallBack` → `dispatchRemoteStreamOutput` in `plugins/file-operations/src/remote_stream.mjs`, keyed by `execId`). `request.mjs` `sessionToChatLog` truncates oversized `role:'tool', name:'shell'` content **at the prompt layer only** (head/tail + temp-file path via `src/scripts/shell_guard.mjs`), so the page keeps the full output. AI `<run-*>` timeout policy (default 3 min, `expect`+`tolerance`, `wait="forever"`) and large-output spill live in the same shared guard, used by `plugins/code-execution`; its `handler.mjs` emits `generation_options.onToolOutput` (`code-execution.run-js` / `run-<shell>` / `inline-*`) with a per-call `callId`, and `request.mjs` sets `remoteToolCallbackPartpath: 'shells/code'` so remote tool output streams back.
- `editor_sources.mjs` `collectEditorSources`: editor project dirs via a self-contained `execJs` lambda on the target machine — scans `User/globalStorage/state.vscdb` (`terminal.history.entries.dirs`) + `User/workspaceStorage/*/workspace.json` (`folder` file:// URL, `%3A`/UTF-8 decoded, leading `/` stripped) across VS Code **and fork variants** (`Code`/`Code - Insiders`/`VSCodium`/`VSCodium Insiders`/`Cursor`/`Cursor - Insiders`/`Windsurf`/`Trae`/`Trae CN`, platform data dirs), plus Notepad++ `session.xml` (win32) and JetBrains-family `options/recentProjects.xml` (`Google/` = Android Studio, `JetBrains/` = IDEA/PyCharm/WebStorm/GoLand/CLion/DataGrip/PhpStorm/Rider…, `<entry key>` + `$USER_HOME$` expansion, other macros skipped). Dirs are deduped by **realpath** (junction/symlink aliases collapse, shorter path kept) and returned sorted by **last active** (dir + child mtimes, depth ≤ 2, skipping `node_modules`/`.git`/etc.). `buildQuickAccess` shows editor-sourced projects as root-view recommendations **even without an active workspace** (siblings + `.git`-bearing subdirs require one), and re-dedups candidates against already-saved workspaces on the machine (same realpath), so a saved workspace never reappears as a quick-access item. Drive roots show their volume label (`C:\ Windows`) via `getVolumeLabels` (`Get-CimInstance Win32_LogicalDisk` on a pwsh-capable shell; exec preset forces UTF-8 output so Chinese labels survive). **Both are memoized with TTL** (`src/scripts/memo.mjs` `memoizePromise`): editor scan 5 min, volume labels 1 h — the root-view browse (the slow part) is served from cache, so opening the workspace picker stays fast. The editor-source cache key includes the **APPDATA/XDG_CONFIG_HOME fingerprint** (same-process env switches, e.g. tests, must not share entries). `boot()` fires a background `browseMachine(machine, '', workspace)` warmup so the first picker open hits the cache.
