# code Shell (AI coding sessions)

opencode-style web layout: topbar conversation selector (aggregated across workspaces) + far-right workspace overview / centered message flow / single-card composer. Machine / workspace / char / mode / AI source / shell pills live **below the input**. Selections and lifetime state live in `localStorage` prefs (`code.shell.<user>.*`); sessions live on the target workspace (`.fount/code/sessions/<id>.json`, written only by the frontend).

## Frontend conventions (public/index.mjs)

- **Layout**: opencode-style — topbar left = `#session-select` dropdown (cross-workspace conversation picker) + `#new-session-button`; center = session title; far right = `#workspace-overview` dropdown (workspaces + per-workspace conversation overview). There is **no left sidebar** — mobile has no drawer. The composer card's `#composer-controls-main` row holds mode / AI source / shell pills below the input (all `dropdown-top`, row must **not** set `overflow: hidden`); a centered `.code-composer-targets` row sits **below the card** with the machine / workspace / char pills (opencode-style).
- **Pill selectors replace native `<select>`**: daisyUI `dropdown` + `.code-pill` (label span + chevron). Menus are rendered by `render*Menu()`; items call `document.activeElement?.blur()` after click (daisyUI 5 trigger gets `pointer-events: none` while open).
- **Dialogs go through templates**: `public/src/templates.mjs` binds `dialogsFor('/parts/shells:code/src/templates')` — `folder_browser`, `command_params`, `char_switch`, `ai_source_panel` live in `public/src/templates/*.html`. Open via `openDialogFromTemplate(name, data, { onReady })`; do not hand-write `<dialog>` in `index.html`.
- **Composer is `createMarkdownRichInput`** (textarea-compatible API). A `contenteditable` element has no `.value` / `.selectionStart` — always read/write via the returned `richInput` (`richInput.value`, `richInput.selectionStart`, `richInput.setRangeText`). Reading `elements.composerInput.value` silently yields `undefined`. Placeholder is mode-dependent: `updateComposerPlaceholder()` swaps the `.fount-markdown-rich-input-placeholder` span text (normal vs shell) **and must also sync the element's `placeholder` attribute** — `markdownRichInput` rebuilds the span from that attribute on every focus/click (`placeCaretWhenEmpty`). Note `setRawText`/`setRangeText` do **not** dispatch `input`; programmatic writes never need a `suppressComposerInput` guard.
- **Shell mode (`！`/`!`)**: entered from an empty composer via the `input` handler; the `！` is **removed immediately** (`richInput.value = ''`) so the user types a clean command. Exits on **Backspace while the whole input is empty** (deleting content down to empty does NOT exit). Shell pill (`#shell-pill-wrap`) shows as the mode indicator; the other controls fade via `.code-composer-shell.shell-mode .code-composer-controls-main > :not(#shell-pill-wrap)`. UI copy uses a single `!`; code accepts both `！` and `!`.
- **Input history + ghost (both modes, independent)**: `historyState` holds `own` (workspace `.agents/fount/code/{shell,message}_history.json`, localStorage fallback for message without workspace) + `native` (shell only). ↑/↓ navigate own history **only when the caret is on the first/last line** (`isAtFirstLine`/`isAtLastLine`); a `.code-composer-ghost` span (`contenteditable=false` + `data-emptySlot` so serialization skips it) shows the prefix-match remainder when the caret is at the end; **Tab / ArrowRight accept the ghost**. `updateGhost` runs after every `input` (markdownRichInput rebuilds the DOM each input, so the ghost is re-added each time).
- **Workspace char override**: on `selectWorkspace`, `applyWorkspaceCharConfig()` reads `.agents/fount/code.json` (`{ char: { partname, install_url } }`) — installed → auto-select; missing → bottom-right `.code-char-recommend` card (install via `runPart('shells/install', ['install', url|partname])`, dismiss is not persisted).
- **`fount run`**: `run` uses the last-active user and the CLI cwd as the workspace; the page is opened with `?workspace=<id>` and `boot()` prefers that query param over the localStorage pref.
- **Locale check / page watch**: rendered message bubbles and the session title are dynamic user/AI text — mark them `user-content` (empty value). Rendered chrome (empty-state, session select menu, workspace overview, pill labels) re-renders via `rerenderDynamicText` on language change. Avoid adding **new i18n keys** on feature branches without syncing ja-JP/en-UK (locale watcher `missing-ja`).
- **Send / stop**: `#send-button` is an icon button (`updateSendButton` swaps arrow-up ↔ stop square + `stop` class). **Ctrl/Cmd+Enter sends**. Tab accepts a ghost when present, else cycles mode (message mode only).
- **Empty states**: `renderEmpty()` inside `#messages` — no workspace → guidance card with CTA that opens `folder_browser`; workspace but no session → "start a new coding session". No empty `div` black hole.
- **Scrolling**: stick-to-bottom auto-scroll (tolerance `SCROLL_TOLERANCE`), "back to bottom" floating button (`#code-back-to-bottom`) appears when scrolled up.
- **`/` commands panel / `@` file autocomplete** consume `state.commands` (merged builtin/global/workspace lists from `GET /profiles`) and `GET /files/search`. Slash panel is a `.code-slash-panel` card anchored above the composer.
- Session flush (single writer = frontend): `markSessionDirty` → flush on `window.blur` / `visibilitychange` / `beforeunload` and immediately when marked while not generating; WS `send` carries the whole session, `done` returns entries + `chat_scoped_char_memory` which replaces local state.
- Register the `onLanguageChange` rerender **inside `boot` after `initTranslations('code')`** — module-top-level registration warns before the bundle loads; module-top-level `geti18n()` also warns.
- **Theming**: `index.css` references daisyUI **full-spelled** semantic vars only (`--color-base-100` / `--color-base-content` / `--color-primary` … via `var()` / `color-mix`) — no `:root` hardcoded fallback, no `--b1` abbreviations. Radius via `--radius-box|field`, border width via `--border`.

## Backend (src/)

- `main.mjs` `ArgumentsHandler(user, args, context)` (also `IPCInvokeHandler`) registers `context.cwd` as a machine-0 workspace (creating it) and opens `/parts/shells:code/?workspace=<id>` via `npm:open` (`config.port` for the URL).
- `request.mjs` builds `chatReplyRequest_t` by hand: world = inline `codeWorld` (injects selected profile + workspace AGENTS.md), plugins = `code-execution` + `file-operations`, request-level `ai_source` / `workdir: {machine, path}`. `triggerCodeReply` resolves world `GetCharReply` first, falling back to the char's `GetReply` — **`await` each candidate explicitly** (`const world = await …GetCharReply?.(…); const reply = world ?? await …GetReply(…)`).
- `runner.mjs` `runShellCommand`: machine 0 without a workdir falls back to `os.homedir()` (never the server cwd / system32).
- `history.mjs`: native shell history files (pwsh/powershell `ConsoleHost_history.txt`, bash `.bash_history`, zsh `.zsh_history`; local via `node:fs`, remote best-effort via `cat ~/…`) + own history read/append at `.agents/fount/code/{shell,message}_history.json` (dedupe, cap 500).
- `workspace_config.mjs`: reads `.agents/fount/code.json` (char override / install URL).
- Targets resolve through `plugins/file-operations/src/target.mjs` (`createTargetExecutor`): machine 0 = local (`node:fs` + exec), machine > 0 = subfount executors. `listMachines(username)` backs `GET /machines` and the AI-facing `<list-machines></list-machines>` tag.
- Sessions are validated with `/^[A-Za-z0-9_-]{1,64}$/` before touching the fs; `GET /sessions/all` aggregates summaries across all saved workspaces (with `workspaceId`/`workspaceName`).
- Shell data gotcha (repo-wide): `saveShellData(username, shell, name)` persists the **in-memory cache entry**, not a passed value — mutate the object returned by `loadShellData` first, or call `assignShellData` to swap the value.

## CLI (repo-wide)

- `fount run <partpath> …` resolves the **last-active user** (`auth/index.mjs getLastActiveUsername`, tracked via `lastActiveAt` on login) — old username-first parsing moved to `fount runas <user> <partpath> …` (`src/server/index.mjs`).
