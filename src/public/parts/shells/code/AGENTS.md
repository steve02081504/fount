# code Shell (AI coding sessions)

opencode-style web layout: sessions sidebar / message flow / composer. Selections and lifetime state live in `localStorage` prefs (`code.shell.<user>.*`); sessions live on the target workspace (`.fount/code/sessions/<id>.json`, written only by the frontend).

## Frontend conventions (public/index.mjs)

- **Layout**: opencode-style — sessions sidebar (`aside.code-sessions`), topbar with session title + pill selectors (workspace / machine / char), centered message flow, single-card composer. Mobile ≤768px: sidebar becomes a drawer (toggle button + backdrop).
- **Pill selectors replace native `<select>`**: workspace / machine / mode(profile) / AI source / shell are daisyUI `dropdown` + `.code-pill` (label span + chevron). Menus are rendered by `render*Menu()`; items call `document.activeElement?.blur()` after click (daisyUI 5 trigger gets `pointer-events: none` while open).
- **Dialogs go through templates**: `public/src/templates.mjs` binds `dialogsFor('/parts/shells:code/src/templates')` — `folder_browser`, `command_params`, `char_switch`, `ai_source_panel` live in `public/src/templates/*.html`. Open via `openDialogFromTemplate(name, data, { onReady })`; do not hand-write `<dialog>` in `index.html`.
- **Composer is `createMarkdownRichInput`** (textarea-compatible API). A `contenteditable` element has no `.value` / `.selectionStart` — always read/write via the returned `richInput` (`richInput.value`, `richInput.selectionStart`, `richInput.setRangeText`). Reading `elements.composerInput.value` silently yields `undefined`. Placeholder is mode-dependent: `updateComposerPlaceholder()` swaps the `.fount-markdown-rich-input-placeholder` span text (normal vs shell) **and must also sync the element's `placeholder` attribute** — `markdownRichInput` rebuilds the span from that attribute on every focus/click (`placeCaretWhenEmpty`), so the span text alone is not enough (the stale `code.composer.placeholder` i18n value would resurface).
- **Locale check / page watch**: rendered message bubbles and the session title are dynamic user/AI text — mark them `user-content` (empty value) or the 3-locale watcher hard-fails on `[test:locale] forbidden-script`. Rendered chrome (empty-state, session list, pill labels) re-renders via `rerenderDynamicText` on language change and must not linger: `appendEntryBubble` removes the empty-state `.code-empty` once the first message lands. Avoid adding **new i18n keys** on feature branches — `update-locales.py` only runs on `master`/CI, so the watcher's ja-JP pass flags them (`missing-ja`) until synced.
- **Pill dropdowns in the composer** open upward: the mode / AI source / shell pill `dropdown` wrappers carry `dropdown-top`, and `.code-composer-controls-main` must **not** set `overflow: hidden` (it clips the absolute-positioned `dropdown-content`). Topbar pills keep default downward opening.
- **Shell mode (`！`/`!`)**: entered from an empty composer via the `input` handler; the `！` stays in the input as the mode hint; shell pill (`#shell-pill-wrap`) shows, controls row fades out, composer gets `shell-mode` class. Exits when the user deletes everything; programmatic `richInput.value = ''` re-triggers an `input` event — guard with `suppressComposerInput`. On send, strip the leading `！` (`value.replace(/^[!！]/, '')`).
- **Send / stop**: `#send-button` is an icon button (`updateSendButton` swaps arrow-up ↔ stop square + `stop` class), disabled/`aria-label` via `code.composer.sendAria|stopAria`. **Ctrl/Cmd+Enter sends**; Tab cycles mode (with toast feedback via `code.composer.modeSwitched`).
- **Empty states**: `renderEmpty()` inside `#messages` — no workspace → guidance card with CTA that opens `folder_browser`; workspace but no session → "start a new coding session". No empty `div` black hole.
- **Scrolling**: stick-to-bottom auto-scroll (tolerance `SCROLL_TOLERANCE`), "back to bottom" floating button (`#code-back-to-bottom` style `.code-back-to-bottom`) appears when scrolled up.
- **Session list**: each item = title + relative time + hover delete button (`confirmAction('code.sessions.deleteConfirm')` → `DELETE /sessions/:id`). Session id validated server-side; frontend only passes ids through.
- **`/` commands panel / `@` file autocomplete** consume `state.commands` (merged builtin/global/workspace lists from `GET /profiles`) and `GET /files/search`. Slash panel is a `.code-slash-panel` card anchored above the composer.
- Session flush (single writer = frontend): `markSessionDirty` → flush on `window.blur` / `visibilitychange` / `beforeunload` and immediately when marked while not generating; WS `send` carries the whole session, `done` returns entries + `chat_scoped_char_memory` which replaces local state.
- Register the `onLanguageChange` rerender **inside `boot` after `initTranslations('code')`** — `onLanguageChange` fires its callback on registration; module-top-level registration warns `[i18n:missing]` before the bundle loads. Module-top-level `geti18n()` also warns — set aria-labels (e.g. `#code-back-to-bottom`) inside `rerenderDynamicText` instead.
- **Theming**: `index.css` references daisyUI **full-spelled** semantic vars only (`--color-base-100` / `--color-base-content` / `--color-primary` … via `var()` / `color-mix`) — no `:root` hardcoded fallback, no `--b1` abbreviations (checks `daisyui_var` / `theme_radius` fail otherwise). Radius via `--radius-box|field`, border width via `--border`.

## Backend (src/)

- `request.mjs` builds `chatReplyRequest_t` by hand: world = inline `codeWorld` (injects selected profile + workspace AGENTS.md), plugins = `code-execution` + `file-operations`, request-level `ai_source` / `workdir: {machine, path}`. `triggerCodeReply` resolves world `GetCharReply` first, falling back to the char's `GetReply` — **`await` each candidate explicitly** (`const world = await …GetCharReply?.(…); const reply = world ?? await …GetReply(…)`). `await a ?? b` only awaits `a`; the un-awaited `b` promise then spreads to `{}` (empty char message).
- Targets resolve through `plugins/file-operations/src/target.mjs` (`createTargetExecutor`): machine 0 = local (`node:fs` + exec), machine > 0 = subfount executors. `listMachines(username)` backs `GET /machines` and the AI-facing `<list-machines></list-machines>` tag handled in `file-operations/handler.mjs`; it tolerates users without a subfount manager by returning localhost only.
- Sessions are validated with `/^[A-Za-z0-9_-]{1,64}$/` before touching the fs; deletion goes through a remote-fs script because the executor has no delete primitive.
- Shell data gotcha (repo-wide): `saveShellData(username, shell, name)` persists the **in-memory cache entry**, not a passed value — mutate the object returned by `loadShellData` first, or call `assignShellData` to swap the value.
