# code Shell (AI coding sessions)

Web layout: left workspace explorer + topbar home button (opens the two-pane workspace / conversation picker) + shared conversation/file tab strip + a right-aligned **context chip** (current workspace / char; opens the pickers) / centered message flow / single-card composer for conversation tabs. Mode / AI source / shell pills and the power icon button live **inside the composer card**; machine / workspace / char pills (`#composer-targets`) and the hint sit **below the card but collapse once the conversation has entries** (`.code-main.empty-mode` is the only state that shows them — see `docs/ui-details.md`). Selections and lifetime state live in `localStorage` prefs (`code.shell.<user>.*`); the opened tab list (draft + session + file tabs) and each conversation tab's unsent composer draft live in **backend shell data** (`code.tabs`, `GET/PUT /tabs`) and sync across pages via `BroadcastChannel` (`fount-code-tabs`); sessions live on the target workspace (`.fount/code/sessions/<id>.json`; the backend is authority during generation — it writes a `is_generating` placeholder at run start and replaces it with the final entries on finish, so a page reset mid-run recovers from disk; the frontend still writes edits / `!` shell results outside generation).

The workspace explorer sits left of the shared tab strip. `public/src/explorer.mjs` lazily browses the active tab's workspace and opens `type: 'file'` tabs beside draft/session tabs; `tabs.mjs` persists these tabs with `id` equal to a workspace-relative path. File buffers stay in the page while switching tabs; switching away from a file tab or losing browser focus saves its edits automatically, and a text-colored dot before its tab icon indicates unsaved changes, and closing a dirty file asks before discarding. `fileEditor.mjs` creates one Monaco model per open file and restores that model's view state across tabs; close and clean refresh dispose models. Dirty state compares Monaco alternative version ids with the saved checkpoint, so edits made during an in-flight save remain dirty. The shared syntax service in `src/public/pages/scripts/components/codeSyntax.mjs` supplies Shiki themes, language grammars and folding to the editor and Markdown fences. The editor uses Monaco's native context menu (plus the shell save action) and matching Monaco message bundles selected by fount's applied UI locale; `onLanguageChange` updates dynamic messages, cached native controls and action labels without replacing models or undo history. User-installed TextMate grammars, file associations and Worker formatters load from the authenticated user's `.fount/editor.json`; contract and example: [editor extensions](docs/editor-extensions.md). The editor uses `/workspace/directory` and `/workspace/file` APIs, saves with a SHA-256 version token; a 409 leaves the buffer intact. Agent run settlement refreshes clean open buffers and the tree. Directory results paginate by `offset`/`limit` (at most 2000 entries per page), with `total` and `nextOffset`; a request without pagination still returns its first 2000 entries. Files up to 16 MiB are supported. Chunk reads use byte offsets with 256 KiB maximum blocks and a SHA-256 snapshot version; the frontend decoder must stream across UTF-8 block boundaries. The backend keeps snapshots for up to 30 seconds in a process-wide cache capped at 32 MiB and 256 files. Backend paths are checked against the canonical workspace root. These routes and their file version / write-lock helpers live in `src/workspace_files.mjs`; `src/endpoints.mjs` only registers them.

**Live refresh** (local and remote): the page subscribes over `WS /ws/parts/shells:code/workspace/watch` with the visible directories (root + expanded ones + the parent dirs of open file tabs). `workspace_watch.mjs` runs the same self-contained producer through `createTargetExecutor(...).openCallbackSession`, backed by subfount's generic callback sessions for remote machines. Initialization returns `ready`; later events remain live independently. The client re-subscribes when the workspace/target/directory set changes, coalesces refreshes, and refreshes after reconnect to cover missed changes. `#code-explorer-connection` shows connecting/disconnected/unavailable; dirty buffers keep edits and gain external-change status. Heartbeats cover both network legs, cancellation releases resources, and a 30 s remote lease covers lost cancellation. **`fs.watch` listeners hold directory handles**: close/navigate away before deleting a workspace. Generic model: [remote-callback-sessions](../../../../../docs/design/remote-callback-sessions.md).

`public/src/changeSummary.mjs` builds the conversation's change card from successful `file-operations.replace-file` / `override-file` tool entries: the plugin writes the edit summary (path, display diff, added / removed counts) into `extension.pluginData['file-operations'].edit`, which the shell's extension whitelist already persists — the card reads that field, never the localized log text. Each file row opens its editor tab and shows a floating line diff on hover or keyboard focus. It summarizes logged tool edits, so changes made through arbitrary JS or shell commands do not appear unless those tools emit a comparable edit summary.

`public/llms.txt` carries only the shell intro and API: any UI / layout / shortcut / button-interaction detail belongs in **this file** or [docs/ui-details.md](docs/ui-details.md), never in `llms.txt`.

Runtime contract (session-scoped runs, per-tab input, completion): [docs/design/code-shell-session-runtime.md](../../../../../docs/design/code-shell-session-runtime.md).

## Frontend conventions & traps

- **Composer is `createMarkdownRichInput`** (textarea-compatible API). A `contenteditable` element has no `.value` / `.selectionStart` — always read/write via the returned `richInput` (`richInput.value`, `richInput.selectionStart`, `richInput.setRangeText`). Reading `elements.composerInput.value` silently yields `undefined`. Placeholder is mode-dependent: `updateComposerPlaceholder()` calls `richInput.setPlaceholderI18n(key)` (`placeholderI18n` option) so the rebuilt `.fount-markdown-rich-input-placeholder` span carries `data-i18n` and retranslates with the locale — do **not** write the span text or the `placeholder` attribute directly (markdownRichInput reads neither once the key is set). Note `setRawText`/`setRangeText` do **not** dispatch `input`; programmatic writes never need a `suppressComposerInput` guard. markdownRichInput re-dispatches an **untrusted** `input` after every content change; the trusted browser `input` arrives first but with the same content, so the composer's `input` handler acts **only on untrusted events** (`if (event.isTrusted || richInput.composing) return`) or every keystroke runs its work (draft sync, slash panel, ghost) twice. The ghost uses `richInput.setSuffixHint(remainder)` (not a hand-appended span) and `richInput.suffixHint` / `commit()`.
- **Message layers**: bubbles render `entry.content_for_show ?? entry.content` (agent `content` vs human `content_for_show`); copy / save-to-gist / download-HTML / drag-export use the show layer, edit edits `content_for_edit ?? content` and clears the show/edit overlays. **Never** collapse the two layers back into one `content` — sessions persist `content` + `content_for_show`/`content_for_edit`/`charVisibility`, and the agent prompt reads `content` only.
- **Markdown rendering regression**: a real persisted reply can leave an orphan bare fence after a tool result and make the rest of a report look like code. `public/src/replyMarkdown.mjs` narrowly repairs that pattern for char *display only*; do not mutate stored content or treat an unclosed language-tagged fence as an error. `test/frontend/stream_render.spec.mjs` checks a multi-round WS conversation, a persisted/reloaded transcript derived from session `9df34984`, and 119-line code-block geometry at desktop/mobile widths. Keep both stream and final/reload assertions when changing reply rendering; a text-only assertion cannot catch the swallowed heading/list or the viewport-height overflow.
- **Streaming traps**: `boot` calls `warmupMarkdownPipeline()` to preheat the markdown pipeline (a cold registry stalls the first preview window); the streaming bubble uses the **trusted** tier (`allowDangerousHtml: true`) so the reasoning `<details>` is visible during generation (a char reply that is mostly tool calls otherwise renders empty); `updateEmptyMode` must treat "currently generating this session" as non-empty (else the streaming bubble is swallowed); the generating bubble is marked `user-content` or the page-watch locale scan warns.
- **Live tool cards**: `tool-output` `start`/`chunk` updates a temporary card in the generating bubble; `end` must remove that card immediately. A generation can continue streaming after a completed `run-js`, and keeping the card until `done` strands it below later text (and duplicates the eventual tool entry). `test/frontend/stream_render.spec.mjs` checks the card and new preview in the same DOM snapshot.
- **Sub-agent runs** (`public/src/subagents.mjs`): a `sub-agent` tool entry carrying `extension.subAgent` renders as a status button (`subAgentCardElement`), spinning while `running`/`summarizing`; clicking opens Agent Studio at `#conversation/subagent%3A<runId>` in a new tab. Live state comes from the server `subagent-run` event (`onServerEvent`, registered in `boot`) filtered by `chat_name === 'code-<sessionId>'`, backed by `GET /api/parts/shells:agent_studio/subagents?chatId=` on tab switch.
- **Unified async tasks** (`public/src/asynctasks.mjs`): a tool entry carrying `extension.asyncTask` renders as a **non-interactive** status card (`asyncTaskCardElement`) — kind icon + label + live state (spinner while running). Live state mirrors sub-agent: the server `async-task` event (`onServerEvent`, registered in `boot`) filtered by `owner.chatName === 'code-<sessionId>'`, backed by `GET /api/parts/shells:code/async-tasks?chatId=` on tab switch (the endpoint lists only running tasks; settled results remain awaitable until the parent generation finishes or they are retrieved, while the completion notification is the persistent record).
- **Shared run-card framework** (`public/src/runCards.mjs`): both modules build their card through `createRunCard` / `paintRunCard` and register a `createRunCardFeed` (per-chat state map + 3 s throttled refresh + `chat_name`/`owner.chatName` event filtering + icon-key repaint). `messages.mjs` / `streamView.mjs` call `updateRunCards()` after (re)rendering; `session.mjs` calls `refreshRunCards({ force: true })` on tab switch (one call for both feeds).
- **Error entry retry**: a char throw appends a system `name: 'error'` entry (`session.mjs` `onSocketMessage`) rendered as a collapsed tool log (`isErrorEntry` keeps it closed; `.code-message:has(> .code-message-error-retry)` pins the feedback bar always-visible). `retryFromError(entry)` splices that entry and everything after it (drops the interrupted round) and re-sends WS `trigger` — same regeneration path as an async-notification resume; a send failure ends the generating bubble and re-renders from the already-spliced session. The `code.message.retry` key sits beside `code.message.regen` in every locale.
- **Structured tool cards**: `messages.mjs` renders `extension.asyncInspect` (`renderAsyncInspect` → role-tagged transcript for sub-agent payloads, plain latest-output markdown for JS/shell), `extension.asyncList` / `extension.asyncAwait` (`renderAsyncList` / `renderAsyncAwait` → snapshot task rows + result markdown; a state badge appears only when the payload carries a terminal `state`, so `<list-async/>` / unsettled rows never fake "running"). The unified `<inspect-async id="…"/>` tool (`async-task` plugin) replaced `<check-subagent>`; there is no `subAgentCheck` render path anymore. `code/src/entry_extension.mjs` `pickEntryExtension` is the whitelist of extensions persisted to the session — a new render field **must** be added there or the WS `done` path strips it (`sanitizeEntry`); the tool-execution-target snapshot `executionTarget` (`{machine, workdir}`) is whitelisted too. Per-entry plugin state lives in the generic `pluginData` namespace (e.g. file-operations' pre-read dedup keyed under `pluginData['file-operations']`, historically `loadedContextHashes`): it is plugin-owned and JSON-serializable, and the shell whitelists only the `pluginData` field itself, never plugin-specific keys. `request.mjs` `sessionToChatLog` preserves `charVisibility` so prompt-side visibility matches the stored entry. **The shell renders tool / system / sub-agent-transcript text with the trusted markdown tier and adds no sanitizer — tool output safety is the producing tool's responsibility** (escape or wrap raw output before logging it; see [plugins/AGENTS.md](../../plugins/AGENTS.md)). Do not add a shell-side sanitizer to compensate.
- **Tool summaries and failures**: the shared reply pipeline stamps tool results with `extension.toolCall = { tag, summary, state }` after each call settles (`succeeded` / `failed` / `pending`), independently for each parallel call. The code shell persists this field, renders the operation beside the localized label as plain text, and gives failed results an error-color border/background plus a localized failure badge. Manual `!` execution uses the same field and checks both `code` and `exitCode`; live tool cards show a bounded code excerpt. Historical entries fall back to the first call fence. Keep tool failures separate from generation-error retry semantics.
- **Tool labels**: `TOOL_NAME_I18N` maps dot-namespaced tool names (`sub-agent.*`, `async-task.list|await`, `async-task` notice, `code-execution.*`) to `code.tool.*`; `code-execution.async` needs the task `kind` (`geti18n('code.tool.async.run', { kind })`). Unknown names fall back to the triggering XML tag, then the raw name.
- **Per-session runtime (`store.runtimes: Map<tabKey, SessionRuntime>`)**: the hard boundary is **the run belongs to the session, input belongs to the tab, DOM only paints the active tab** — the old `store.generating` / `generatingSession` / `generatingRunId` / `recovering` / `pendingFiles` / `dirtyTabKey` globals are gone. `store.mjs` freezes `tabKeyOf(tab)` / `activeTab()` / `getRuntime(tabKey, { create })` / `getActiveRuntime()` / `isGenerating(tabKey)` (`generating`|`stopping`) / `isBusy(tabKey)` (`status !== 'idle'`); a runtime holds `{ tabKey, session, status: 'idle'|'submitting'|'generating'|'recovering'|'stopping', runId, previewText, liveTools, attach, attachments, revision, savedRevision, flushTarget, flushError }`, and the active runtime's `session` is always `store.session`. Every UI decision (send/stop button, empty mode, regen visibility) reads the active runtime only, so a background tab generating never blocks the composer. Module map: `store` (state) · `tabs` (strip / menu / BroadcastChannel / URL) · `session` (load / activate / delete, draft + shell-mode restore) · `sessionPersistence` (per-tab flush queue) · `generation` (shared WS, per-session run routing, attach/recover) · `streamView` (streaming bubble + live tool cards, driven by runtime caches) · `submission` (single send entry) · `shellExecution` (`!`) · `attachments` (per-tab queue) · `completion` (settled sound/unread) · `messages` (bubbles / actions / scroll) · `composer` (input / history / slash / mention).
- **`submission.mjs` is the single send entry** (`submitMessage`): snapshot the target (`tabKey` / session / machine / workdir / charname / ai_source / profile / text / attachments) **before the first `await`**, set `status='submitting'` (blocks re-submit), optimistically append the user entry, then clear the sent draft text + attachments **only after** the request is dispatched (input typed meanwhile is kept); a failed dispatch rolls back the optimistic entry and keeps the draft/attachments retryable. `send` accepts **files-only** (content and files: at least one non-empty). Slash commands, `fount.user.send`, external prompts, regen and error-retry all route through it.
- **Workspace switch readiness**: `selectWorkspace` (`pills.mjs`) is the one step that moves composer content between tabs — `activateDraftForWorkspace` rebinds the active draft when it has **no workspace binding or no unsent text** (a non-empty draft bound to another workspace keeps its tab and the switch opens a new draft), and `restoreTabDraft` re-applies the rebound tab's draft. That tail must therefore finish before anything reports the switch as done: only `selectWorkspace` renders the workspace pill label, and the folder browser's `onSelect` merely adds the workspace and awaits it. The label is the readiness signal callers (and `selectWorkspaceViaBrowser`) key on — rendering it earlier, e.g. straight after `addWorkspace`, lets input typed in the meantime be cleared by the tail. `test/frontend/tabs.spec.mjs` pins both halves by holding `/sessions/all`.
- **Backend run identity + persistence**: every WS `send`/`regen`/`trigger` carries a client `runId`; the backend echoes `runId` + `sessionId` on **every** frame after a leading `{ type: 'run-start' }`, and the frontend drops frames whose `runId`/`sessionId` don't match the runtime's current run (`isCurrentRunFrame`). The backend registers one active run per `username\0sessionId` (a new request aborts the previous one, marking it `superseded`) and persists the authoritative session — an `is_generating` placeholder before generation, final entries on `done`/`aborted`/`error`. `ws.close()` only detaches the socket; generation continues and still lands on disk. **Multi-socket observation**: `run.sockets: Set<WebSocket>`; WS `attach` adds the caller and replays `run-start` + `run.buildReplayEntries()` (id-deduped), and a closed socket removes only itself. `abort` carries `sessionId` (required) + `runId` (optional) and is ignored when `runId` doesn't match the current run, so a late stop can't abort the next run. On reload / socket loss `recoverGeneration(runtime)` first tries `attachToRun` (≤3 s for `run-start`; `no active run`/timeout → false) so an in-progress run re-enters generating state and keeps streaming; otherwise it polls `GET /sessions/:id` until the placeholder is gone (`hasGeneratingEntry`), then times out after 2 min into a `recovering` state with a manual reconnect button (`retryRecovery`) — it never pretends to be idle. Composer `input` (non-history-nav) sends a throttled (1 s) WS `typing` frame so the backend resets the deferred `agentFinish` timer.
- **`code-run-settled` event**: after a run reaches a terminal state **and persists**, the backend emits `sendEventToUser(username, 'code-run-settled', { chatName: 'code-<sessionId>', sessionId, workspaceId, runId, status: 'done'|'error'|'aborted' })`; superseded runs do not dispatch, and the `error` path dispatches even when persistence failed. The WS terminal frames and this event share `completion.handleRunSettled`, idempotent per `runId`. Runs started with no socket (wake / hook regen / job resume) broadcast `code-run-started`, and an open page enters the generating state via WS `attach`.
- **Completion semantics (`completion.mjs`)**: a run's completion sound plays **unconditionally, once per `runId`** — not gated on the source tab, focus, `suppressed`, or notification permission (deduped via `localStorage` + Web Locks so multiple pages don't double-play); the unread dot is added only when the settled tab isn't the visible+focused active tab and clears on activation. The code OS notification carries `options.data.suppressPageSound` so `base.mjs` skips its own page sound (the code shell plays it).
- **Session flush (frontend edits; backend owns generation)**: `markSessionDirty(session)` finds the owning tab key, bumps that runtime's `revision`, promotes a draft tab to a session tab (`onTabPromoted`), and flushes immediately unless that tab is generating/recovering; `sessionPersistence` runs one serial write queue per `tabKey` and flushes all dirty tabs on `window.blur` / `visibilitychange` / `beforeunload`. The WS `send` carries the whole session, `done` returns entries + `chat_scoped_char_memory` which replaces local state. `submitMessage` optimistically appends the user entry (with `clientEntryId`) before the round-trip; the backend skips echoing when that id is already in the incoming `session.entries`. While a tab is generating/recovering the frontend skips flushing **that tab** (the backend is the writer) — other tabs flush independently; the backend merge is `baseEntries + allNewEntries + requestSession.entries` deduped by id.
- **Incremental entries (append during generation)**: an agentic reply spans many rounds, so the backend emits `{ type: 'entries-append', entries }` **before** each `preview` — `endpoints.mjs` `flushIncrementalEntries` reads `requestSession.generationResult.logContextBefore` (exposed by `request.mjs` `replyPreviewUpdater`; the char template fills `base_result`), tracks an `emittedLogCount` watermark, and `done`/`aborted`/`error` only send the remainder. The frontend `streamView.mjs` `insertIncrementalEntries` dedupes by id and inserts each fresh bubble **before the generating bubble**, so completed tool logs / earlier rounds append live instead of the whole reply flushing at `done`.
- **`fount run`**: `run` uses the last-active user and the CLI cwd as the workspace; the page opens with `?workspace=<id>` and `boot()` prefers that query param over the localStorage pref.
- **`fount.user.send`**: boot registers `globalThis.fount.user.send(string | chatLogEntry)` — same syntax as chat (`normalizeUserSendPayload`); `content.content` goes to the current session, `files[]` join the attachment queue.
- **a11y (`[test:a11y]`)**: axe `label-content-name-mismatch` compares an element's **CSS-visible** text with its accessible name, and `aria-hidden` text **still counts as visible** — so a decorative initial must be CSS-generated content (`content: attr(data-initial)`), never a text node inside a labelled button. Any element carrying an `aria-label` must include its visible text in that label; when the label mixes in user data (workspace / character / session / file names), compose it at render time and mark `user-content="aria-label"` so the page-watch locale scan skips that attribute. Verified patterns: `tabs.mjs` `tabAriaLabel` + `.code-tab-avatar::before`, `pills.mjs` `renderContextChip`, `attachments.mjs` `renderMessageAttachments`.
- **Locale check / page watch**: rendered message bubbles and the session title are dynamic user/AI text — mark them `user-content` (empty value); tool/system bubbles and structured prompt cards (tool logs, sub-agent transcripts) are prompt content — mark them `prompt-content`. Rendered chrome (empty-state, home picker rows, tab strip, pill labels) re-renders via `rerenderDynamicText` / `refreshHomePicker` on language change; menu chrome items built with `menuItem` should pass `i18nKey` (→ `data-i18n`, auto-retranslated) rather than `geti18n()` text, and JS-rendered pill-label fallbacks use `setElementI18n` (clear `dataset.i18n` when showing data). Playwright selects chrome via `[data-i18n="…"]` — `hasText` only for user/data text (char / source / profile names, paths), never localized chrome ([test/playwright.md](../../../../scripts/test/docs/playwright.md)). Avoid adding **new i18n keys** on feature branches without syncing ja-JP/en-UK; page-watch rotates only zh-CN → ja-JP → en-UK, so **en-UK must be real Latin text**.
- Register the `onLanguageChange` rerender **inside `boot` after `initTranslations('code')`** — module-top-level registration warns before the bundle loads; module-top-level `geti18n()` also warns.
- **Theming**: `index.css` references daisyUI **full-spelled** semantic vars only (`--color-base-100` / `--color-base-content` / `--color-primary` … via `var()` / `color-mix`) — no `:root` hardcoded fallback, no `--b1` abbreviations. Radius via `--radius-box|field`, border width via `--border`. Shared Shiki code syntax uses the light/dark theme pair in `pages/scripts/components/codeSyntax.mjs`; that service updates both Markdown token colors and Monaco's native theme when `onThemeChange` fires. Markdown's Shiki CSS selectors depend on the `color-scheme` **attribute** set by `preload.mjs` / `theme/index.mjs` (`updateColors`) — the `[color-scheme*="…"]` selectors in `pages/scripts/features/markdown/convertor.mjs` never match the old `documentElement.colorScheme` expando. Write only the attribute; `base.css` derives the CSS `color-scheme` property from it (do not also set `style.colorScheme`).
- **Icons**: no hand-written `<svg>` (enforced by `checks:no_manual_svg`); icons come from the Iconify CDN as `<img class="text-icon">`, inlined by `renderTemplate` / `svgInliner`, or by `applyTheme()` for static page icons. `public/src/icons.mjs` `fileIcon` gets file-type artwork from `material-file-icons` (esm.sh; `getIcon` owns filename/extension matching) and serves it as a **percent-encoded SVG data URL** — it deliberately does not match `svgInliner`'s `img[src$=".svg"]` selector, so those icons keep the package's own fixed colors and are not theme-tinted.

Deep UI (layout, home picker, tabs, folder browser, shell mode, history/ghost, slash/mention, bubbles, tool cards / async tasks, message actions, attachments, power actions): [docs/ui-details.md](docs/ui-details.md).

## Backend (src/)

- `main.mjs` `ArgumentsHandler(user, args, context)` (also `IPCInvokeHandler`) registers `context.cwd` as a machine-0 workspace (creating it) and opens `/parts/shells:code/?workspace=<id>` via `npm:open` (`config.port` for the URL). `--prompt|-p` and `--workspace|-w` (default CLI cwd) are parsed by `parseRunArgs`; with a prompt the backend first tries to hand off to an **open page** (`requestExternalOpen` broadcasts a `code-open` event with a nonce, waits ≤800 ms for a page to `POST /open-claim`); if none claims, it opens the page with `?prompt=` (boot creates a draft tab and sends immediately). The claiming page creates a draft tab in the target workspace, focuses/flashes via `flashWindowFocus`, and sends the prompt.
- **Workspace hooks** (`src/hooks.mjs` + pure `src/hooks_config.mjs`): `.agents/fount/code.json` `hooks.agentStart|agentFinish|agentsIdle` are shell-command lists run on code top-level runs **and** sub-agent runs (sub-agent events come from the internal `events.on('send-event-to-user')` `subagent-run` stream, filtered to `chat_name` starting with `code-`). Agent counts are per workspace (`machine\0path`); a top-level run's `agentFinish` is **deferred 13 s** via the pure `src/finish_scheduler.mjs` (keyed `username\0sessionId`): a WS `typing` frame resets the timer, and a new run (`send`/`regen`/`trigger`) cancels it (`endpoints.mjs` `cancelAgentFinish`) so the hook only runs for the next completed run. The delayed finalize runs the hook **before** incrementing on a hook-triggered regen and **before** the counter decrements, so a hook-triggered regen never trips `agentsIdle`. Event data is passed as `FOUNT_CODE_*` env vars (see `public/llms.txt`). A non-zero `agentFinish` exit feeds merged stdout+stderr back as a system entry and triggers a regen (≤`MAX_REGEN_ATTEMPTS`=3 per session, reset on success); the attempt counter is persisted as `session.regenAttempts` so the cap survives restarts, and a user `send` clears it. `detached` entries run via `launch_external` (local only) with optional `singleton`. `setHookRuntime({ regen })` injects the endpoints-side regen (`regenCodeSession`) to avoid a module cycle.
- `runner.mjs` `runShellCommand` accepts `env` (local only, merged with `process.env` via `target.execShell`'s `env` option) and `timeoutMs` (default `null` = unlimited, preserving user `!` command semantics); hooks pass an explicit timeout.
- `request.mjs` builds `chatReplyRequest_t` by hand: world = inline `codeWorld` (injects selected profile + workspace AGENTS.md), `plugins: {}` (the shell injects no default plugins — each char declares/merges its own set, e.g. `code-execution` / `file-operations` / `async-task` / `sub-agent`, in its `GetReply`), request-level `ai_source` / `workdir: {machine, path}`, and `extension.generationId` (per-round id that sub-agent runs use as `parentId`). `triggerCodeReply` resolves world `GetCharReply` first, falling back to the char's `GetReply` — **`await` each candidate explicitly**. The parent generation is recorded by the char template's active-recording calls (`request_record.mjs`), keyed by the request's `chat_id` (`code-<sessionId>`) and labeled `source: 'shells/code'` from `extension.agentStudio`; the shell no longer writes records itself.
- **XML tool diagnosis**: a streaming preview placeholder confirms only that display recognized a tag, not that its handler executed. Check final raw char content and `logContextBefore` for tool entries; `<view-file path="package.json"/>` previously parsed as an empty body and silently stopped the regen loop. Reproduce via the code WS with an explicit tool-only first turn and verify a tool log plus a second AI round.
- **Async code execution** (`async-task`): `<run-js async="true">` / `<run-<shell> async="true">` returns a unified task id immediately; results are delivered as a system notification unless awaited. `<list-async/>` / `<await-async>` manage one or more tasks (`mode="all|any"`). JS is still in-process and uninterruptible, async or not. `GET /async-tasks?chatId=` reads the in-memory registry (`plugins/async-task/registry.mjs`, same module instance the plugin loads) for running tasks of the chat. `entry_extension.mjs` holds the extension whitelist for session persistence.
- **Async completion notification**: `registry.mjs` `deliverNotification` calls `appendAndWake(channel, entry)` — `AppendChatLogEntry` writes a **char-visible system entry**, then `RequestCharReply` asks for a wake. The **backend** decides and starts wake runs (`src/runs.mjs`); the frontend only merges/renders. For any `role !== 'char'` append `AppendChatLogEntry` broadcasts the `code-session-entry` display event so an open page merges it immediately (char replies are carried by the generation stream and `done`, so no event). With a live run it also writes into the run's authoritative `run.requestSession.entries` plus `run.allNewEntries`, so `buildFinalEntries` persists it and the `attach` replay (`buildReplayEntries`) carries it — the terminal `done`/`aborted`/`error` frames list only the entries the run appends itself, so an appended entry reaches an attached client through the `entries-append` broadcast (and a page through `code-session-entry`). A run that already entered its `finalizing`/`completed` tail is awaited first (re-reading `activeCodeRuns`), so a late append lands in the next run or on disk instead of a snapshot that was already persisted. With no run it loads the workspace session, persists the entry, then broadcasts the same event. `RequestCharReply` → `requestCodeRunStart`: if `codeWakes.isRunning(sessionKey)` it only `mark`s the wake (the running run's `Update({ forRound: true })` consumes it via `snapshot`/`observe`), otherwise it starts a `trigger` run. A run owns a `codeWakes` slot from `tryBegin` and `release`s it in `finally`; an unobserved wake starts exactly one follow-up run unless the run was `superseded` by a newer one (which reads the wake from disk). Runs started with no socket (wake / hook regen / job resume) broadcast `code-run-started`; an open page enters the generating state and sends WS `attach`, and the backend replays `run-start` + `run.buildReplayEntries()` (all `allNewEntries` plus requestSession-only appends, id-deduped) so the page paints history and receives the rest of the stream.
- `runner.mjs` `runShellCommand`: no workdir falls back to the **target machine's** `os.homedir()` via `execJs` (never the server cwd / system32). User `!` commands run **without a timeout** (`timeoutMs: null`) and return `elapsedMs`. AI `<run-*>` timeout policy (default 3 min, `expect`+`tolerance`, `wait="forever"`) and large-output spill live in `src/scripts/shell_guard.mjs`, shared with `plugins/code-execution`. Streaming plumbing (local `@steve02081504/exec`, remote `callback`): [docs/ui-details.md](docs/ui-details.md).
- `lifecycle.mjs`: per-user active-generation counter + pending power actions (`Map<machine, action>`). Every WS `send`/`regen` calls `beginCodeGeneration` and the `finally` calls `finishCodeGeneration`; at 0 with pending actions it runs each host's OS power action (`shutdown` / `sleep` / `restart`) via `createTargetExecutor(...).execShell(null, cmd, { timeoutMs: null })` — remote hosts first, local delayed ~800ms so the `done` response gets out. On successful `done` it fires `notifyCodeCompletion` → `notifyUserI18n` → `notifyUser` (live `/ws/notify` → Web Push → desktop fallback; shared lib `src/server/web_server/notify/`).
- `retention.mjs`: session retention cleanup. Last-activity time is the session file's filesystem **mtime** (generation/edits write the file; `GET /sessions/:id` calls `touchSession` which `utimes`-touches it without changing content). `listSessions` returns each summary's `mtimeMs` via `readTextFileWithMtime` (executor primitive). Days come from shell data `code.retention.days` (default `DEFAULT_RETENTION_DAYS`=30; `0` disables). `pruneInactiveSessions` deletes sessions whose mtime is older than the cutoff, skipping sessions with an unsent draft (a session tab with non-empty `draft`) and generating ones. Triggered lazily/throttled (6h per user+workspace) by workspace selection (`PUT /workspaces/:id/use`) and synchronously by `POST /sessions/cleanup`; `GET/PUT /retention` read/write the days.
- **Exit/resume boundary**: `src/shutdown.mjs` installs synchronous signal listeners alongside `on-shutdown` and records process-level state via `scripts/stopping.mjs`. Ordinary `process.exit` stops launching new AI rounds (templates call `finishToolRound(args, prompt_struct)` at each regen boundary — it refreshes round entries, then continues unless the shell's optional `generation_options.finishRound` returns explicit `false`; absent = continue; nested sub-agents read injected `deps.isStopping`), awaits the current AI call + reply handlers and session write; `SIGINT`/`SIGTERM`/`SIGHUP` abort active calls (templates call `signal.throwIfAborted()` after `StructCall`), allow up to 3 s for cleanup, and retain the job. For workspace-backed runs, the `StartJob` snapshot carries only `{sessionId, workTarget, ai_source, profile}` (no session content — sessions always live in the workspace `.fount/code/sessions`, never in `config.json`) and precedes the generating placeholder; successful persistence of completed/explicitly aborted runs calls `EndJob`. `interfaces.jobs.ReStartJob` starts a detached resume from the workspace session after boot, strips the placeholder, appends a system notice with the shutdown reason + elapsed gap + workspace-cleared note, and re-enters the same generation path. (`coderunner_workspace` is runtime scratch: kept in memory across calls but stripped in `sessions.mjs` `saveSession`, so it never lands on disk or in a job snapshot.) Session HTTP writes/deletion return 409 while the job or run exists. `finishRound` also commits the finished round so forced aborts never persist a half-written round.
- **System sleep**: `src/scripts/sleep_watch.mjs` checks 1 s ticks for gaps over 5 min. Sub-agent deadlines and shell/JS/async-await timers exclude detected sleep, and code/sub-agent conversations receive a system notice; test synthetic gaps via `checkForSleep` and always restore a mocked clock afterward.
- `history.mjs`: native shell history files (pwsh/powershell `ConsoleHost_history.txt`, bash `.bash_history`, zsh `.zsh_history`) via a self-contained `execJs` lambda + own history at `.agents/fount/code/{shell,message}_history.json` (dedupe, cap 500).
- `workspace_config.mjs`: reads `.agents/fount/code.json` (char override / install URL).
- `editor_sources.mjs` `collectEditorSources`: editor project dirs from a self-contained `execJs` lambda (VS Code + forks, Notepad++, JetBrains family); deduped by **realpath**, sorted by last active. Editor scan (5 min) + volume labels (1 h) are memoized with TTL (`src/scripts/memo.mjs`); the editor-source cache key includes the **APPDATA/XDG_CONFIG_HOME fingerprint**. `boot()` warms it in the background. Details: [docs/ui-details.md](docs/ui-details.md).
- Targets resolve through `plugins/file-operations/src/target.mjs` (`createTargetExecutor`): machine 0 = local (`node:fs` + exec), machine > 0 = subfount executors. `listMachines(username)` backs `GET /machines` and `<list-machines>`.
- Sessions are validated with `/^[\w-]{1,64}$/` before touching the fs; `GET /sessions/all` aggregates summaries across all saved workspaces (with `workspaceId`/`workspaceName`). Opening/using a workspace best-effort ensures its `.gitignore` lists `.fount/code/sessions` (only for git repos / dirs that already have `.gitignore`; memoized per machine+path).
- Shell data gotcha (repo-wide): `saveShellData(username, shell, name)` persists the **in-memory cache entry**, not a passed value — mutate the object returned by `loadShellData` first, or call `assignShellData` to swap the value.

## CLI (code shell)

- `fount run code` opens the web page; explicit CLI options select terminal execution. Terminal capabilities are read only by the caller-side CLI module and are not sent through IPC. `fount run code --cli [--session <id>] [--prompt <text>]` starts the interactive terminal; `--print` forces one-run output: terminal stdout defaults to text, redirected stdout defaults to NDJSON. `--output-format ndjson|text` forces print mode and chooses the format. NDJSON writes `JSON.stringify` of each newly committed message entry, including the user entry; it has no event envelope, preview chunks or start/end record. If stdin or stdout is not a TTY, `--cli` falls back to print mode. In print mode, provide `--prompt` / `--prompt-file` or `--attach` with `--session`. `Run` honors the caller-provided `isTTY` when present, reports a closed stdout pipe as exit 1 instead of an unhandled stream error, and keeps stdout to the run's committed entries (session ID, runId and diagnostics go to stderr).
- Options and slash commands are documented by `fount run code --help` and in `public/llms.txt`. Session files and CLI drafts are keyed by workspace and session ID. The active-run registry is serialized by username + session ID, so reuse of one ID across workspaces still contends; attach/abort additionally validate the selected workspace and run ID. Check `cli/commands.mjs` for exact command behavior.
- The interactive client subscribes to the user event bus (`/ws/notify`) through `transport.events` + `client.subscribeServerEvents`, filtered to `code-<sessionId>`: `code-run-started` attaches to a run the CLI did not start (wake / hook / job resume), `code-session-entry` merges an appended entry, and `code-run-settled` rings the terminal bell once per `runId` and refreshes an idle transcript. `--attach` uses the same path, so an interactive session keeps following later runs instead of exiting after one.
- `/diff [path]` prints the accumulated `extension.pluginData['file-operations'].edit` summary (`path  +added -removed`, plus the read-only diff when a path is given) through `transcript.mjs` `collectFileEdits` / `formatFileEdits`. `/export [--html] [path]` writes the text transcript or a standalone offline HTML document (`cli/export_html.mjs`, lazy `marked`, raw HTML from tool output neutralized — that escaping is deliberate export policy, not a shell-side renderer sanitizer).
- The TUI transcript uses `cli/view.mjs` for cached per-entry Markdown layouts and display-only `<details>` / `<think>` disclosures, including unfinished streaming blocks; fenced and inline code remain literal. User entries render immediately from the submitted client session. Click disclosure titles or focus them with Shift+Tab, use arrows to navigate and Enter to toggle; Escape or clicking the composer returns input focus. PageUp/PageDown scroll one viewport, Ctrl+Home/Ctrl+End jump to the start/latest entry, and reaching the bottom resumes stream following. Empty/short transcripts cannot detach from the bottom. Tab on a slash-command prefix opens built-in command completion; Tab elsewhere selects the model. Command output stays in a local scrollable transcript and is never sent to the agent or persisted as session history.
- The terminal UI strings live under `code.cli.tui` in the shared locale files. Keep the input hint aligned with Enter-to-send, Shift+Enter newline, Shift+Tab disclosure focus, `/help`, and Ctrl+C stop/clear/exit. `--tui-mode fullscreen` uses the terminal alternate screen; `regular` paints on the main buffer with the same full-screen renderer and does not guarantee native scrollback.
- `ArgumentsHandler` can return `{ type: 'output', content }` or `{ type: 'run-js', module, args, data }`. The generic caller dispatcher (`src/scripts/part_invoke_result.mjs`, which also owns `DEFAULT_IPC_PORT`) imports `Run(context)` from the selected part root and passes `stdin` / `stdout` / `stderr` / `cwd` / `ipcPort` / `signal` / `onCleanup`; the result has no version field, and `run-js` modules own their own exit code and cleanup. `data.usageError` is the server-side "rejected before the client could start" channel (workspace validation) that `cli/main.mjs` prints with exit 2 — the CLI still parses its own args for the exit code. Do not add code-shell branching to generic dispatch.
- The TUI saves a per-workspace/per-session draft while editing and restores it when reopening that session; retention treats nonempty CLI drafts as active-session protection. Automated pure checks cover component logic, not manual Windows terminal IME, OSC52 clipboard compatibility, or real-terminal input behavior. Do not describe those as verified without a real-terminal check.
- **Integration tests must settle the workspace before deleting it**: `startCodeRun`'s `finally` removes the run from `activeCodeRuns` *before* `dispatchAgentFinish`, the wake follow-up and the last `persist` have run, so a test that deletes its temp workspace as soon as `!activeCodeRuns.has(key)` sees a late atomic write (`mkdir -p` + write + rename) recreate `.fount/code/sessions` — which the framework's temp-leak check then reports as residue (`fount test` exit 3). `wake_append.test.mjs` `removeWorkspaceSettled` polls the directory tree to quiescence and retries the removal; reuse that shape for any test that runs a real generation in a temp workspace.

- Model usage lives in `extension.usage = { calls, total }`; the extension whitelist persists it. `session.usage` is the incurred task aggregate, built from the stored total plus the current generation usage on each persistence pass. Deleting or regenerating messages keeps incurred usage; PUT session edits preserve the stored aggregate. Every bubble whose entry carries `extension.usage` shows that entry's own figures (char replies, compression summaries, async-task notices) and the session-wide total sits above the transcript, while the CLI prints its own per-entry usage plus the header total; copy comes from `code.usage.*` in the shared locales, with plain-English fallbacks in the CLI. Token fields with unknown values stay absent, and money shows the known cost of priced calls; unpriced calls contribute no monetary value. A failed or interrupted run keeps the calls it already incurred in its own `name: 'aborted'` / `'error'` system entry (skipped when no call was recorded), so the page, the CLI transcript and NDJSON export all see that usage. The submitted user entry is broadcast as its own `entries-append` right after `run-start`, so a client that never inserts optimistically (the CLI) still receives it while the page dedupes by id.
