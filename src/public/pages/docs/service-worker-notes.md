# Service Worker Notes

Rules and traps for `scripts/service_worker.mjs` (+ pure `service_worker_policy.mjs`) and the page-boot waits in `base.mjs`. Overview: [AGENTS.md](../AGENTS.md).

- **Authenticated responses are never cached**: `/api/`, `/ws/`, `/virtual_files/` (network-first; `shouldCacheResponse` refuses them) — those responses are per-user authenticated and must not linger in Cache Storage or be shared across users. Cold-boot mode flips only from a same-origin **navigation** request (`/`, `/index.html`, or `?cold_bootting=true`) — never from a sub-resource / `fetch` or a cross-origin request — so authenticated data is never served from Cache Storage.
- **Upgrading a cross-origin request to `cors` must drop credentials** (`corsUpgradeInit`): HTML gives no-cors subresources (`<img>` / `<link>` without `crossorigin`) credentials mode `include` while CDN / avatar hosts answer `Access-Control-Allow-Origin: *`, so a credentialed cors fetch is refused by CORS (the browser logs the wildcard error) and nothing ever gets cached; that cors fetch is what the consumer gets, so a missing / un-ok readable response falls back to the request's own mode (opaque, credentials as the browser set them).
- **`fetchAndCache` keeps the real failure reason on `Error.cause` and logs it as its own line** — a bare `fetch failed for <url>` says nothing, and a restarting server / cold boot is the usual cause; the fetch failure itself is a `warn` because the callers log `error` once nothing can serve the request.
- **Every page-boot wait on the worker goes through `waitWithTimeout`** (`base.mjs`: controller ready, `WAKE_SERVER_REQUEST` reply, version query) — when the browser refuses the registration (`NotAllowedError` in incognito / embedded WebView / third-party-blocked origin) `navigator.serviceWorker.ready` never settles, and an unbounded await leaves the start page spinning forever, so the default-part request and the unauthenticated login fallback never run.
- **Server reachability (`queryWakeServer`) must not use a fixed deadline**: the probe runs the `WAKE_SERVER_REQUEST` query and a `/api/ping` timing request in parallel, and `scripts/lib/serverReachability.mjs` derives the verdict budget from the measured round-trip (×1.5, floor `WAKE_PROBE_MIN_BUDGET_MS`, plus a half-RTT grace before re-checking) — a fixed value (it used to be 500 ms) misjudges every slow channel (tunnel/proxy: `/api/ping` takes seconds) as "server down" and fires the `fount://` protocol handler, which the browser then reports as an error. Whichever of the two answers first wins (`firstPositive`), the in-flight probe is aborted once the worker approves, and the controller wait ends as soon as the registration is refused — so a browser that denies Service Worker registration does not pay the 5 s controller cap on every page boot (`startPageServiceWorkerWait` asserts that).
